About "Metro & Bus Fare Calculator with Dynamic Pricing"

Architecture Overview

This web application is developed to calculate passenger transit fares across multimodal urban transit networks. It demonstrates clean architecture, design patterns, algorithmic shortest-path search, dynamic pricing logic, and robust database persistence.

Backend (Java Spring Boot)

  • Layered Architecture: Controller, Service, Model, Repository
  • Strategy Design Pattern for interchangeable pricing rules
  • Graph representation and Dijkstra's Shortest Path Algorithm
  • Spring Data JPA & Hibernate ORM

Database (MySQL)

  • Database: transit_fare_db
  • Table: fare_history with indexing
  • Stores complete audit history of all calculated fares
  • Automatic DDL schema generation and query optimization

Frontend (HTML/CSS/JS)

  • Clean, responsive Blue & White transit dashboard
  • Vanilla JavaScript with asynchronous fetch() API calls
  • Real-time HTML5 Canvas demand visualization
  • Zero bulky framework dependencies; lightning-fast execution

Design Pattern & Algorithmic Highlights

1. Strategy Design Pattern (GoF Behavioral Pattern)

Defined an interface FareCalculationStrategy implemented by DistanceBasedFareStrategy, ZoneBasedFareStrategy, and PeakOffPeakFareStrategy. The FareStrategyFactory dynamically selects the calculation algorithm at runtime based on the client request, ensuring the Open/Closed Principle (OCP) is strictly maintained.

2. Dijkstra's Algorithm for Shortest Path

Employs a weighted undirected graph representation of the transit network with a priority queue (min-heap) to determine the lowest distance route between any two origin-destination station pairs.

3. Dynamic Peak/Off-Peak Pricing

Applies economics-based dynamic pricing to flatten peak ridership curve, calculating peak demand surcharges and rewarding off-peak travel with saver discounts.
